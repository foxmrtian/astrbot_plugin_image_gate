# 图片功能守门（astrbot_plugin_image_gate）

> **插件由 冬瓜 与 丹宝 合作完成。**

一个给 **Gitee AI Image**（`astrbot_plugin_gitee_aiimg`）做权限收口的独立插件：
把生图相关功能**按功能拆成独立开关 + 独立放行名单**，管理员始终放行，其他人逐项放行。

## 为什么做成独立插件

主插件会被上游更新**整包覆盖**，补丁写进它的 `main.py` 会被冲掉。
本插件独立存在，主插件怎么更新都不影响它。

## 功能清单（7 项，各自独立开关）

| 功能 key | 覆盖内容 | 对应命令 |
|---|---|---|
| `draw` | 文生图 | `文生图` `aiimg` `生图` `画图` `绘图` `出图` `预设列表` `重发图片` |
| `edit` | 改图 | `aiedit` `图生图` `改图` `修图` `改图帮助` |
| `selfie` | 自拍 | `自拍` `自拍参考` |
| `video` | 视频 | `视频` `视频预设列表` |
| `batch` | 批量生图 | `批量` |
| `task` | 任务查询 | （工具 `aiimg_task_status`） |
| `characters` | 人物 / 形象 | `形象` `人物` `换形象` |

## 配置说明

每项功能有两个配置：

- `{功能}_enabled`：**总开关**。关掉 → **除管理员外**所有人都不能用。
- `{功能}_allow`：**额外放行名单**。填 `sender_id`（QQ 号 或 微信 openid），一行一个。
- **管理员始终放行**（认 AstrBot 的 `admins_id`），**无视总开关、也无需写进名单** ——
  所以管理员有好几个时，不用往每个分项里逐个添加。
  - 例：只给某个群友开「改图」→ 把 `edit_enabled` 保持开，把他的 QQ 号填进 `edit_allow`，其它 `*_allow` 留空。

另有 `deny_message`：无权限时的提示语，默认「这个功能没你份」。

## 拦截原理（两层硬闸，都在代码里）

1. **LLM 工具层**：`on_llm_request` 钩子里，按功能把生图工具**从请求里直接摘掉** ——
   模型根本看不到这些工具，想调都调不出来。
2. **命令层**：`/画图` `/改图` `/自拍` `/视频` 等命令，按功能逐项 `stop_event` 掐断并回话。

> 关键点：**不靠模型「自觉判断身份」**。规则是代码写死的，绕不过去。

## 已知限制（重要）

- **画图 / 改图 / 自拍共用一个 LLM 工具**（`aiimg_generate`，靠 `mode` 参数区分），
  工具层没法再细分。所以本插件采取**安全策略**：
  > 只有 `draw`、`edit`、`selfie` **三个都放行**时，才保留这个共用工具；
  > 只要单独放行其中一部分，LLM 层的生图工具会被**整体摘掉**。
  >
  > 此时**命令层仍可用**（仍是逐项精确控制），只是模型不能再主动调用生图工具。
- 视频 / 批量 / 任务查询 / 人物 是 1:1 对应工具，逐项精确控制，无此限制。
